1

Attach the file

Drag it in, or click and choose it. The name and size show so you can check it is the right one.

2

Number and title

The number is checked as you type. A tick means it is free. A red message means it is already used.

3

Pick a reason

Choose the closest match from the list: design change, client comment, vendor data, and so on.

4

Write the summary line

One line. What changed, and why. Keep it under 280 characters. See Screen 6 for good examples.

5

Pick the checker and approver

Two different people. Neither can be you. The checker reads the file. The approver signs it off.

6

Send for check

The file is now waiting for the checker. It is not current yet. It becomes current only after approval.

The form will stop you. A red message under a field tells you what is missing. For example: “Summary needs 20+ characters” or “Approver must be different from the checker.”

Writing a good summary line
✓“Moved pump 300 mm north after the site survey.” Says what changed and why.
✗“Updated.” Says nothing. Nobody can tell what changed.
✗“Fixes as discussed.” Says nothing specific. Discussed where?

Quick checklist

Before you add a file

  • I have the file and its final number
  • I know what changed, in one line
  • I have picked a checker and approver
  • Neither of them is me

When you check

  • I opened the file, not only the summary
  • The summary matches what I see
  • If wrong, I returned it with a reason

Never

  • Approve your own file
  • Write “updated” as a summary
  • Try to erase a file. Remove it instead
